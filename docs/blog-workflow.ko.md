# 블로그 워크플로 가이드

[English](blog-workflow.md) | [한국어](blog-workflow.ko.md)

`blog-writing-workflow`는 각 사용자가 자기 블로그의 글과 문체 프로필을 이
저장소에 공개하지 않고도 에이전트에게 블로그 운영 방식을 알려줄 수 있게
합니다. 재사용 가능한 스킬은 공개하고, 생성된 프로필은 사용자에게 남깁니다.

## 1. 스킬 설치

먼저 프로젝트 범위 설치 계획을 확인합니다.

```bash
./scripts/install.sh \
  --target all \
  --scope project \
  --root path/to/blog \
  --skill blog-writing-workflow
```

계획을 검토한 뒤 `--apply`를 붙여 다시 실행합니다. 호스트가 새 스킬을 발견할
수 있도록 에이전트 세션을 새로 열거나 다시 시작합니다.

## 2. 블로그 최초 초기화

자연어로 요청합니다.

> 이 블로그의 메타데이터, 문체, 발행 프로필을 초기화해줘. 생성한 프로필은
> 로컬에만 두고, 확실하지 않은 추론은 적용 전에 나에게 보여줘.

워크플로는 다음을 수행합니다.

1. 글 본문을 저장하지 않고 Markdown 구조를 집계합니다.
2. 최근 글과 구조가 다양한 글을 제한된 범위에서 살펴봅니다.
3. 측정한 패턴, 추론한 문체, 작성자가 밝힌 선호를 구분합니다.
4. 작성자가 검토할 `.agent-blog/blog-profile.md`를 만듭니다.

프로필은 영구적인 성격 모델이 아닙니다. 사이트 형식, 독자, 작성자 선호가
실질적으로 바뀌었을 때 갱신합니다.

## 3. 일상적인 글 관리

요청 예시는 다음과 같습니다.

> 이 메모로 내 블로그 프로필에 맞는 초안을 작성해줘. 발행은 하지 마.

> 내 주장과 확신 정도를 바꾸지 말고 이 초안을 다듬어줘.

> 발행 전 점검을 실행하고 아직 막힌 항목만 알려줘.

> 검토한 초안을 이 블로그에 설정된 방식으로 발행하고 공개 페이지까지 확인해줘.

초안 작성과 점검은 발행 권한을 포함하지 않습니다. 발행은 명시적으로 요청해야
하며, 결과를 다시 확인하기 전까지 원본 초안을 보존합니다.

## 4. 공개 범위 결정

개인 프로필이라면 `.agent-blog/`를 추적하지 않습니다. 팀이나 공동 출판물은
공유 편집 규칙만 담긴 프로필을 검토한 뒤 커밋할 수 있습니다. 자격 증명,
비공개 대화, 내부 URL, 복사한 글 본문은 포함하지 않습니다.

프로필은 경향과 결정을 기록합니다. 모든 작성자를 같은 일반적인 문체로 만들거나
기존 글의 독특한 표현을 복사하지 않으면서 일관성을 유지하는 것이 목적입니다.
